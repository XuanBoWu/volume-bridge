# 音桥 UI 方案

本文定义 VolumeBridge（音桥）的日常操作界面、状态表达、权限引导和后续 UI 实现边界。目标是让用户在不理解 Core Audio 内部实现的情况下，快速知道当前控制的设备、软件音量是否生效，以及出现问题时应该做什么。

## 设计原则

### 原生 macOS 优先

- 主界面采用状态栏图标 + `NSPopover`，点击图标打开，点击外部或按 Esc 关闭。
- 使用 AppKit 原生控件、系统字体、系统阴影和系统圆角。
- 浅色/深色外观跟随系统；不固定浅色或深色背景。
- 控件强调色使用系统 `controlAccentColor`，不使用品牌橙或图标中的橙色。
- 状态颜色只使用 macOS 语义色，并始终同时提供图标和文字，不依赖颜色单独表达。
- 不使用渐变、玻璃拟态、彩色卡片、固定品牌色或装饰性 3D。

图标可以保留既定的金门大桥造型和配色；菜单栏面板、HUD、按钮和状态区不继承图标的橙色。

### 用户心智模型

音桥是位于系统输出与显示器之间的软件音量层。用户只需要理解“当前输出”“软件音量”“键盘音量键”和“音频链路”，不需要看到 Process Tap、Aggregate Device、IOProc 等实现术语。

- **软件音量已启用**：音桥正在处理当前显示器输出。
- **由 macOS 控制**：设备有原生音量，音桥自动旁路。
- **等待输出设备**：没有可用的显示器音频输出。
- **正在恢复**：设备或音频服务变化，音桥正在重建链路。
- **已暂停**：音桥停止处理，输出恢复到原始音量。
- **需要权限**：键盘音量键或音频捕获权限尚未完成。

暂停或退出会恢复显示器的原始播放音量，这条规则要在主界面持续可见。

## 主面板

主面板使用固定宽度约 320 px 的 Popover，按以下顺序组织：

```text
┌────────────────────────────────┐
│  音桥                    …     │
│  软件音量控制                   │
├────────────────────────────────┤
│  当前输出                       │
│  ● Mi Monitor                   │
│    DisplayPort · 48 kHz         │
│  软件音量已启用                 │
├────────────────────────────────┤
│  显示器音量                     │
│  −  ━━━━━━━━━●━━━━━━  ＋        │
│                 72%        静音 │
├────────────────────────────────┤
│  键盘音量键              已启用 │
│  按 F10 / F11 / F12 调节        │
├────────────────────────────────┤
│  音频链路                       │
│  ● 正在处理当前显示器输出       │
│  [暂停软件音量]   [重建链路]    │
├────────────────────────────────┤
│  设置                           │
│  登录时启动                 ○   │
│  权限与诊断                  ›   │
│  打开日志文件夹                  │
├────────────────────────────────┤
│  退出音桥                       │
└────────────────────────────────┘
```

### 顶部区域

- 显示“音桥”或“VolumeBridge”。
- 显示当前整体状态摘要。
- 不放与日常调节无关的技术信息。

### 当前输出区域

显示设备名称、连接方式和采样率。设备名过长时截断并在辅助文字中保留完整值。

设备由 macOS 原生控制时，显示“由 macOS 控制”，软件音量滑块不可操作但保留在界面中，避免用户误以为功能消失。

### 软件音量区域

- 滑块为主控件，支持连续拖动、方向键、0/50/100 精确端点。
- 保留现有拖动期间不被后台刷新覆盖的同步策略。
- `−` 和 `＋` 按钮分别执行一个标准步进。
- 静音为独立按钮，正常显示“静音”，静音后显示“取消静音”。
- 音量百分比始终可见，静音时同时显示“已静音”。

### 键盘音量键区域

显示“已启用”“需要系统授权”或“暂不可用”。未授权时按钮打开系统设置，并说明只监听音量加、减和静音，不读取普通键盘输入。

### 音频链路区域

- `暂停软件音量` 与 `继续软件音量` 根据状态切换。
- `重建链路`为恢复操作，正常时弱化，错误时提升为主要操作。
- 暂停说明始终提示“显示器会恢复使用原始输出音量”。

## 按钮和功能范围

第一版主面板只提供这些操作：

1. 音量滑块。
2. 音量减少/增加。
3. 静音/取消静音。
4. 暂停/继续软件音量。
5. 重建音频链路。
6. 打开系统设置完成媒体键权限。
7. 打开日志文件夹。
8. 退出音桥。

设置与诊断页面可以提供：

- 登录时启动。
- HUD 显示开关。
- 标准步进与细调步进说明。
- 音频捕获权限和键盘权限状态。
- 复制诊断摘要。
- 导出诊断包。

高级页面不展示音频原始数据，不提供保存或上传音频的功能。

## 首次启动和权限

首次启动显示轻量引导卡片，不阻塞滑块使用：

```text
欢迎使用音桥

音桥可以让你用滑块和键盘音量键
控制不支持原生音量的显示器。

✓ 显示器音频输出
✓ 软件音量链路
! 键盘音量键需要系统权限

[打开系统设置]  [稍后设置]
```

音频捕获权限和键盘音量键权限分开显示。用户可以先使用滑块，再稍后开启键盘权限。

每个权限状态包含：已启用、需要授权、检查中、无法检测。权限问题必须说明缺少什么、为什么需要、去哪里开启。

## 异常状态

### 无输出设备

显示“没有检测到显示器音频输出”和“请连接 HDMI 或 DisplayPort 显示器”，提供“重新扫描”。滑块禁用但不隐藏。

### 原生音量设备

显示“当前设备由 macOS 控制音量”，说明音桥已自动旁路，不修改硬件音量。

### 恢复中

显示“正在恢复音频链路”，暂时禁用可能冲突的控制，同时保留日志入口。

### 恢复失败

显示“音频链路需要恢复”，说明音桥在恢复期间保持安全状态，提供“重建链路”和“打开日志”。不直接把错误码作为主文案。

## 状态栏图标与 HUD

状态栏图标只负责快速识别：

| 状态 | SF Symbol |
| --- | --- |
| 正常 | `speaker.wave.2.fill` |
| 静音 | `speaker.slash.fill` |
| 暂停 | `pause.circle` |
| 等待/恢复 | `ellipsis.circle` |
| 睡眠 | `moon.zzz` |
| 错误 | `exclamationmark.triangle` |
| 旁路 | `speaker.wave.2` |

HUD 保持不抢焦点、自动隐藏和当前音量反馈。它使用系统 HUD 外观，不使用品牌橙。

## 无障碍与本地化

- 每个按钮有完整 accessibility label 和状态。
- 滑块支持 VoiceOver 读取当前百分比和静音状态。
- 颜色不是唯一状态来源。
- 文案、辅助说明、错误提示和权限说明全部进入英文/简体中文资源。
- 长设备名和长本地化文案必须截断或换行，不得撑破 Popover。
- 支持键盘导航和 Esc 关闭。

## 实施顺序

### 第一阶段：主面板

- `NSStatusItem + NSPopover` 外壳。
- 顶部状态、当前输出、软件音量和音频链路区域。
- 保留现有音频控制、媒体键、HUD 和日志逻辑。
- 状态图标动态变化。

### 第二阶段：权限与诊断

- 权限状态卡片和系统设置入口。
- 复制诊断摘要。
- 打开日志目录和导出诊断包。

### 第三阶段：设置与验收

- 登录时启动开关。
- HUD 设置。
- 浅色/深色模式、VoiceOver、长文案和错误状态验收。
- 长时间运行、设备拔插、音频服务重启、权限撤销和媒体键恢复验收。

## 验收标准

- 打开面板后一次交互即可调节音量。
- 用户在 5 秒内能判断当前音量是否由音桥处理。
- 权限问题能直接进入对应系统设置。
- 没有输出、旁路、暂停和恢复失败都不会显示误导性的可用滑块。
- 不改变已有音频处理线程、增益曲线、退出清理和滑块同步约束。
- 浅色、深色、高对比度和 VoiceOver 下信息仍完整。
