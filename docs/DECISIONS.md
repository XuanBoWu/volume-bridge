# 关键决策与问题背景

这些决策解释已有代码为何这样实现，避免换会话后重复试验或删掉保护逻辑。日期：2026-10-08；应用图标一节为 2026-10-09，音量提示音一节为 2026-10-18。

## 设备级软件音量

Mi Monitor 的 DP 音频没有可写原生 VolumeScalar。已验证 Process Tap 在本机衰减、重新播放的技术路径，不需要虚拟驱动或显示器 DDC。Tap 排除自身进程并使用 mutedWhenTapped，避免原声与处理声同时播放。物理设备作 Aggregate 主时钟，Tap 做漂移补偿。

兼容条件收窄到已验证的 HDMI/DP 单流双声道交错 Float32。原生可调设备旁路，其他设备暂不处理。后续扩展必须添加设备与格式证据，不能直接删除条件。

## 百分比与音频线程

0–100% 是应用的软件音量，映射 `(percent/100)²`，所以 50% 的 PCM 幅度为 25%。100% 为单位增益，不放大；0% 收敛为精确零。约 4 ms 平滑，左右声道一帧共享同一个增益，避免左右收敛不同。

实时回调仅处理采样/原子状态，监听、重建、存储和文案查找放在其他线程。保留同设备重建的旧静音 Tap，直到新链路成功，防止恢复间隙漏出原始音量。声学峰值尚未测量，不能把此设计当成完全无瞬态的证明。

## 100% 后滑块跳回

用户实际发现滑块到 100% 后拖不回或被弹回。原因是定时 UI 刷新拿到后台旧快照，覆盖正在拖动的值；单纯更改音频增益不能修复。

TrackingSlider 在 `super.mouseDown` 外报告拖动起止；VolumeSliderState 在拖动和等待后台确认期间保留本地最新值，匹配 Float 转换后的目标再确认。设备切换清掉旧等待状态；后到的媒体键通过操作序号接替鼠标等待，旧异步完成不能覆盖新操作。这些行为由专门回归测试保护。

## 媒体键边界

使用系统媒体事件 Tap，解析音量三键及按下/释放/重复，静音重复不反复切换。只有实际默认输出与 active 链路一致时拦截，匹配释放也要一致处理，其他情况下交回系统。

UI 先判断是否可处理，音频队列再次校验 UID/状态，并根据队列最新值累计调整。这样处理快速连按和设备变化时的竞态。默认步长 6.25%，Shift+Option 1.5625%，音量加减解除静音，静音保留百分比。

系统媒体控制权限已由用户在原版授予。当前 macOS 27 中文页面名称为「设备控制和数据访问」，旧系统可能显示「辅助功能」；权限说明应按现场系统名称判断，不把一个版本的名称当作所有版本固定名称。

## 正常退出的嵌套运行循环

音频停止异步完成后，AppKit 的 terminateLater 可能在嵌套运行循环等待。普通主 dispatch 队列完成回调曾造成退出无法完成。现使用 CFRunLoopPerformBlock，覆盖 common/default/modal 模式，保留该处理及正常退出验收。

## 应用图标

图标由用户逐轮选定：先在 6 个方向里选了「桥 + 音量」的思路，再选金门大桥，最后选晴空国际橙配色。用户还特别纠正过视角：侧面看金门大桥时，近侧塔柱挡住远侧，塔楼是实心的。所以定稿统一画侧视图，塔身是实心阶梯柱身，主缆翻过塔顶鞍座。主缆的抛物线和音桥的平方增益曲线同形，吊索由短到长表示音量；主缆下垂比真实桥更深，是为了保留这个形状。

本机没有 Xcode，用不了 Icon Composer 和 Asset Catalog，所以用系统自带的 `iconutil` 打包 `.icns`。SVG 用 headless Chrome 渲染，再用 ImageMagick 在线性光下按整数倍面积平均缩小。这两样只在重新生成图标时需要，普通构建只复制已提交的 `.icns`，App 本身仍无第三方依赖。

小尺寸不直接缩小主图：直接缩小时，12 根吊索在 32 px 以下会糊成一片紫色。因此 16/32/64 px 各画一个简化、对齐像素的版本；16 px 的主缆逐个像素放置，避免抗锯齿混色。完整规则、验证与设计历程见 `docs/ICON.md`。

## 名称、标识与 Git

用户已经选择音桥 / VolumeBridge，即使已有近似名称也继续使用。项目目录和二进制使用英文，界面按语言显示名称。当前保留 `local.alexwu.DisplayVolume` Bundle ID 和设置域，便于沿用设备 UID 音量；公开发布时再设计正式标识、迁移与签名。

Projects 中的本仓库是开发源，原输出保留备份。只做本机 Git，不擅自远程发布、开源或选择许可证。初始迁移提交为 `21ccc70`，历史验收记录保留原型名称和版本。

## 本地开发签名

ad-hoc 签名的 designated requirement 绑定当前构建的 `cdhash`，重编译后可能让 TCC 保留旧条目却不再匹配当前应用。开发机通过 `scripts/setup-local-signing.sh` 在登录钥匙串中创建一次 `VolumeBridge Local Development` 自签名证书，`build.sh` 固定使用同一身份；其 designated requirement 以证书指纹和 Bundle ID 识别，跨普通重编译保持稳定。自签名只解决本机开发身份，不提供 Developer ID、Gatekeeper 信任或公证；正式分发仍需 Apple Developer Program 和 Developer ID。

## 本地日志

排查权限、设备切换和 Core Audio 恢复问题需要跨进程生命周期保留事件，因此不能只依赖终端 `stderr` 或临时状态 JSON。日志采用应用自己的 JSONL 文件，由串行日志队列写入；普通事件异步写入，错误和严重事件同步写入后再返回。文件按 1 MiB 轮转，最多 12 MiB、保留 14 天，并由启动清理和 6 小时定时任务共同维护。实时 IOProc 只更新原子计数，禁止文件 IO、等待日志队列或写入音频内容。

## 输出切回后的媒体键监听

用户再次报告切换音频设备再切回来后键盘失效。现场日志中音频已恢复 active，但没有后续音量键记录；旧版本只检查监听端口 valid/enabled，实际切换实验也确认它一直复用同一个 Tap ID。该状态检查不足以证明事件送达，具体系统内部丢失原因尚未确认。

恢复软件接管时以设备 UID、设备 ID、音频 generation 作为会话标识，主动重建媒体键监听；经历非接管状态后切回同一会话也重建。这样覆盖快速切换、同设备音频重建和设备 ID 变化，而稳定会话不反复重建。旧监听先禁用、再停 RunLoop，并通过代次丢弃已入主队列的旧回调。新增音量包接收/透传/接管日志，只记录音量三键，不记录普通按键。系统监听替换、应用处理入口和用户物理按键验收分开记录。

## 音量提示音

用户要求调节音量时有和原生方案一样、能体现音量大小的提示音。提示音必须绕过 Tap 和 DSP：本进程已被设备级 Tap 排除，若再把提示音送入捕获链路，会被二次衰减并可能重叠。因此直接以目标输出设备的 UID 播放系统自带的 `volume.aiff`，播放前把 `NSSound.volume` 设为 `(percent/100)²`，与软件增益使用同一条曲线且只应用一次。

系统文件缺失时，用内存中合成的短衰减音回退，不新增第三方依赖，也不把音频写入磁盘。播放和停止在独立反馈队列执行，不进入实时 IOProc、媒体事件 Tap 线程或生命周期队列。正常按键必须立即发声，因此合并窗口只设 20 ms，用于折叠同一批重复事件，不能用来给人类按键节奏限速；每次播放都重启声音，读取最新音量，避免 0.38 秒的声音层叠。提示音请求放在界面刷新之前，减少连按时主线程 UI 工作造成的排队延迟；滑块只在松手且后台确认后响一次，不随拖动连续发声。

静音、0%、暂停、旁路、等待、睡眠、错误、无目标设备或设备 UID 不一致时保持安静；静音、切换设备、暂停和退出会取消待播放项并停止当前声音。提示音是合成/系统提示，不是用户音频，不写入日志或磁盘。真实听感、长按节奏和不同音量下的响度仍需用户实机验收。

## 本地化与交接

使用原生 `.lproj/Localizable.strings` 和 `InfoPlist.strings`，Swift/Objective-C++ 从同一 Bundle 取文案，英文作为 development region。百分比按区域格式化，语言选择由 macOS 的首选语言匹配。完整句子翻译，机器状态和诊断字段保持稳定；不在实时回调查找文案。

文档以 AGENTS 为入口、STATUS 为动态进度、ARCHITECTURE/DECISIONS 为稳定约束、TESTING 为可重复步骤、ICON 为图标专题、ROADMAP 为任务清单。源码版本、离线检查、实机版本、用户验收必须分开记录。
